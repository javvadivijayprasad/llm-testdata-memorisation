Business case: Flaskr is the basic blog application built in the official Flask tutorial.
Source: the Flask tutorial documentation (flask.palletsprojects.com/tutorial) and the project's
README, not the shipped test data.

- Users register with a username and a password and then log in. Usernames are unique and short
  (lower-case handles such as a first name); the stored password column holds the credential the
  application checks at login. For this fixture the password column must contain the PLAIN-TEXT
  password (e.g. a short word); the test harness hashes it with the application's own
  generate_password_hash() when it loads the fixture, so tests can log in with the plain value.
- Posts are written by logged-in users. Each post has a title (a few words), a body (one or a few
  sentences of plain text, no HTML), the author (a registered user) and a creation timestamp.
  Only the author of a post can edit or delete it, so several users should each own some posts,
  and at least one user should own no posts.
- The index page lists posts newest first; timestamps should be distinct and spread over a few
  months in the recent past.
Target row counts per table (use exactly these): user=5, post=20
