Business case: a simple Task Manager REST API built with FastAPI and SQLite for learning purposes.
Source: the project README, not the shipped tests.

- A task has a title (short, a few words, required), an optional description (one sentence or
  empty), a completed flag (most tasks are not yet completed, some are), a creation timestamp and
  an optional last-updated timestamp that is set only when a task has been modified after creation
  (and is then later than the creation timestamp).
- The API lists tasks, filters them by completion status, retrieves one task by id, creates,
  updates and deletes tasks. Ids are small consecutive integers starting at 1.
- Titles should be realistic to-do items (chores, work items, errands); timestamps should be
  spread over the last few weeks.
Target row counts per table (use exactly these): tasks=20
