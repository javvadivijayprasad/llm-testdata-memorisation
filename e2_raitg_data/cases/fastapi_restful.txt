Business case: a RESTful web service (FastAPI, SQLite) implementing CRUD operations on a Players
resource — the Argentina squad at the 2022 FIFA World Cup. Source: the project README and its REST-client examples (rest/players.rest;
nanotaboada/python-samples-fastapi-restful), not the shipped database.

- Each player has a first name, an optional middle name, a last name, an optional date of birth
  (an ISO-8601 timestamp string such as 1992-09-02T00:00:00.000Z), a squad number, a playing
  position (Goalkeeper, Right-Back, Centre-Back, Left-Back, Defensive Midfield, Central Midfield,
  Attacking Midfield, Right Winger, Left Winger, Centre-Forward) with its abbreviation (GK, RB,
  CB, LB, DM, CM, AM, RW, LW, CF), a club team, the club's league, and a flag saying whether the
  player is in the starting eleven (exactly eleven players should be).
- The squad number is unique and is the key used by the API to retrieve, update and delete a
  player (numbers 1–26; a POST with an existing squad number is rejected with 409). The id is a
  UUID string.
- Names are Spanish/Latin-American football names; clubs are real-world-style European and
  Argentine clubs with their leagues (Premier League, La Liga, Serie A, Ligue 1, Liga Profesional).
Target row counts per table (use exactly these): players=26
